## 원인과 수정

1. r38의 00:245A 호출은 화면 지우기를 예약하고 돌아온다. 실제 표시 반영 전 소스 맵과 타일을 다시 바꿔 잔상이 생길 수 있었다. C807 완료 응답까지 확인한 다음 새 그림과 글꼴을 준비한다.
2. 소환수 목록과 소환수 도감에서 매번 96개 그림 타일을 압축 해제하고 작은 전송 단위별로 기다리던 처리를 제거했다. 기존 원본 픽셀을 빌드 시 동일하게 풀어 DF:4000에 저장하고, 현재 페이지에 배치한 그림 타일만 읽는다. 최대 8마리 페이지는 32개 타일, 미발견 항목은 전송하지 않는다.
3. 정적 목록 한글 글리프는 LCD 상태를 검사하고 VRAM에 쓸 수 있는 구간에 짧게 전송한다. VRAM 뱅크 선택은 각 전송의 인터럽트 보호 구간 안에서 복구한다. LCD가 꺼진 초기화 경로는 원래 큐를 사용한다.
4. 목록 지우기를 WRAM 맵에 직접 모아서 처리한다. 화면 폭·행 수·원래 그림·세이브 레코드는 유지한다.

## 실행 확인

독립 Mesen에서 정확한 최종 r39 ROM을 확인한 뒤, 보유 소환수 양쪽 페이지와 사용자 스크린샷에 해당하는 소환수 도감의 미발견/일부 발견/전체 발견 페이지를 확인했다.

- 미발견 도감 페이지: 입력 후 8프레임 안에 표시 확인.
- 일부 발견 페이지 복귀: 16프레임 안에 표시 확인.
- 긴 이름 8개를 포함한 보유 목록/도감 페이지: 24프레임 안에 표시 확인(60fps 환산 약 0.4초).
- 갱신 중 목록을 비운 상태와 완성 상태를 모두 확인했다. 위 프레임 수는 관찰 시점의 상한이며 정확한 최소 시간이나 모든 페이지의 속도 보장은 아니다.
